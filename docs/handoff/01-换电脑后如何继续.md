# 换电脑后如何继续维护

这份仓库应当可以脱离原公司电脑继续使用。换机后不需要先恢复公司源码，也不应把公司源码当作本仓库的依赖。

## 1. 新环境启动顺序

1. 克隆本仓库。
2. 阅读根目录 `AGENTS.md` 和 `README.md`。
3. 阅读 `docs/evidence/01-事实指标与待补证台账.md`，先掌握哪些能讲、哪些待确认。
4. 在 `tracking/00-当前状态.md` 更新日期、目标岗位、当前面试和本周重点。
5. 选择一个具体任务：项目口述、知识复习、JD 匹配、模拟面试或简历优化。
6. 让 Codex 在改动前先说明会读取哪些材料，完成后检查事实台账和敏感信息。

如果目标是改善沟通、业务理解或工作方式，再读 `docs/reflection/01-第一段互联网工作复盘.md`、`docs/study/05-三个月能力改善计划.md` 和 `tracking/03-能力改善计分板.md`。

如果目标是继续城市异动诊断 Agent，先读 `docs/city-agent/README.md` 和 `tracking/04-城市Agent实施进度.md`。先选择“生产方案深化 / 个人合成数据作品”轨道；个人作品只能使用合成/公开数据和从零实现的通用代码，不能依赖原公司环境。

## 2. 新会话可以直接复制的提示词

```text
这是我的长期项目复盘与面试仓库。请先完整阅读 AGENTS.md、README.md、
docs/evidence/01-事实指标与待补证台账.md 和 tracking/00-当前状态.md。
遵循证据等级，不把方案写成上线成果，不把离线指标写成生产 SLA；
项目材料只保留业务问题、关键技术判断、量化结果和高频面试追问，
不要堆版本路由、配置键、普通 Java 实现等琐事。
先告诉我你理解的当前求职主线、三个项目状态和本次任务，然后继续。
未经我明确确认，不要修改 main.tex、提交或推送。
```

## 3. 仓库自身应保存什么

- 能独立理解的项目背景、业务目标和个人职责；
- 指标口径、结果表、限制和失败实验；
- 脱敏的数据血缘、特征分组和线上输入输出契约；
- 系统架构、关键技术决策、替代方案和风险边界；
- 面试讲法、题库、复习计划和进度；
- 外部岗位/JD/面经的日期化快照与原始链接；
- 简历候选素材及其证据状态。

## 4. 不把原公司环境当作未来依赖

文档中若发现原公司绝对路径、内部平台标识、提交哈希、代码类名或接口名，应删除或脱敏，只保留不依赖原环境的自然语言结论；不能因为同时补了自然语言说明，就继续把内部标识留在个人 Git。未来原路径消失后，核心材料仍应可读。

以下原环境只可作为当下核验源，不应成为长期运行依赖：

- 阈值/Agent 和换电策略的公司源项目；
- 公司 Git、Hive、监控、审批、日志、配置中心或在线特征环境；
- 当前电脑中的 Codex 历史、附件与本地 memory。

## 5. 每次更新的最小动作

- 新拿到一个项目数字：更新事实台账，注明时间、样本、对照和证据。
- 新看一个 JD：按岗位筛选表打分，不因标题含“算法/Agent”就直接判断。
- 新完成一次面试：当天填写面试复盘，拆成项目、知识、编码和表达问题。
- 新学一个主题：在题库中标记“能定义/能比较/能设计/能结合项目”四个层级。
- 新完成一个城市 Agent 阶段：先更新实施进度、事实边界和实际评测，再更新项目总结；规划门槛不能直接迁移成成果。
- 准备改简历：先在候选素材中改，核验后再同步到 `main.tex`。

## 6. 备份与完整性

离开当前电脑前至少确认：

- 个人远端仓库权限正常，另一设备可访问；
- 本地待保留 Markdown 都已纳入 Git；
- 没有密钥、Cookie、内部链接、真实日志和公司源码；
- `main.tex` 可用 XeLaTeX 构建，但当前阶段仍以内容核验为先；
- 重要指标在仓库中有文字口径，而不是只存在截图；
- 需要保留的个人公开论文链接可在公网访问；
- 完成一次全新目录 clone 验证后，再把原电脑交还。
