# 个人 Agent Harness / Eval 作品计划

目的：补齐当前简历最明显的能力证据——可公开、可运行、可评测的 Agent 工程作品。它不是复刻滴滴系统，不使用任何公司代码、数据、Prompt 或业务命名。

实施节奏见[三个月能力改善计划](05-三个月能力改善计划.md)。这个作品同时用来练习需求对齐、周状态、风险升级、Demo 和效果复盘，过程材料使用[项目管理与汇报模板](../../templates/项目管理与汇报模板.md)，不能只留下最终代码。

## 1. 推荐题目

> 一个“证据驱动的个人求职研究 Agent”：读取公开 JD 和个人脱敏能力档案，调用只读工具提取要求、生成匹配分析、标记证据缺口，并输出可追踪的准备计划。

为什么适合：

- 数据全部来自公开岗位和本仓库个人材料；
- 能自然展示 Tool、RAG、Context、State、Eval、Trace 和 Human-in-the-loop；
- 结果直接服务求职，容易持续维护；
- 不触碰公司知识产权。

## 2. A0：确定性 Workflow

- 输入一个 JD 文本或公开 URL；
- 提取职责、必需项、加分项、地点/年限等硬条件；
- 映射到统一能力 taxonomy；
- 从事实台账检索对应个人证据；
- 生成“匹配/缺口/不可声称”三栏报告；
- 用户确认后写入本地 tracking，不自动投递。

验收：10 个不同 JD 都能输出合法 Schema；硬条件不遗漏；没有个人证据时明确 UNKNOWN。

## 3. A1：Agent Loop 与工具

最小工具：

1. `read_profile_evidence(query)`：只读个人脱敏证据；
2. `extract_job_requirements(text)`：结构化 JD；
3. `search_public_job(url_or_query)`：获取公开岗位；
4. `score_match(job, evidence)`：确定性评分；
5. `build_study_tasks(gaps)`：生成候选任务；
6. `save_review(draft)`：必须人工确认后保存。

状态至少记录：目标岗位、来源时间、要求、证据引用、未知项、工具轨迹、成本、最终决策。

验收：有最大步数和总时限；工具失败时能降级；写入工具默认关闭且需确认。

## 4. A2：RAG 与 Context

- 对本仓库 Markdown 建小型索引；
- 支持稀疏 + 稠密混合召回和 Rerank；
- 返回文档路径与段落引用；
- 区分长期职业事实、时点市场信息和当前任务状态；
- Context 按“规则 → 任务状态 → 必要证据 → 当前 JD”装配；
- 旧 JD 带时间戳，不能覆盖新快照。

验收：建立 30–50 条检索问句，测 Recall@K；故意加入过期岗位，验证时效排序。

## 5. A3：Eval 与可观测性

离线集建议包含：

- 10 个明确匹配岗位；
- 10 个标题相似但职责不匹配岗位；
- 5 个硬条件不满足岗位；
- 5 个信息缺失岗位；
- 10 个事实冲突或证据不足案例。

指标：

- 硬条件提取准确率；
- 能力要求 micro/macro F1；
- 个人证据引用准确率；
- 不支持事实的拒答率；
- 工具选择与参数正确率；
- 最终报告人工评分；
- P50/P95 延迟、Token 与费用；
- 平均工具步数、失败恢复率。

Trace 保存模型/Prompt/知识索引/工具版本、每步输入摘要、结果和错误类别，不保存秘密或完整敏感上下文。

## 6. A4：安全与工程化

- URL 域名白名单和内容长度上限；
- Prompt Injection 测试；
- 本地文件只读范围；
- 写入前 Diff 和人工确认；
- 超时、重试、限流和熔断；
- SQLite/PostgreSQL 状态持久化、checkpoint、暂停恢复和重复执行幂等；
- Docker 与最小 CI；
- README、架构图、Demo、评测报告和已知限制。

## 7. 技术选择原则

- 先用原生 Python/Pydantic 写清状态和循环，再考虑 LangGraph 等框架；
- 向量库选轻量方案即可，作品价值在检索/Eval，不在组件数量；
- 模型通过可替换接口接入，避免把作品绑定单一供应商；
- 不为展示名词而上 Multi-Agent；单 Agent + 确定 Workflow 足够时就保持简单；
- 每个新增模块都必须有对应评测或故障场景。

## 8. 面试价值

完成后可以诚实地说：

> 我的公司项目证明了高风险 AI 执行链路；个人项目则进一步实现了可公开的 Agent Harness、混合检索、状态恢复和轨迹级 Eval。我可以分别说明两套系统的业务边界和评测结果。

不能说它证明了大规模生产流量、企业知识库或多 Agent 线上经验。
