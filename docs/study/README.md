# 面试复习系统

目标不是“把所有 AI 知识重新学一遍”，而是用最短路径恢复三种能力：

1. 能把自己的项目讲到经得起连续追问；
2. 能围绕目标 JD 设计一个生产级 Agent/ML 系统；
3. 能在有限时间完成 Python 编码、基础原理和工程问题。

## 1. 优先级

| 模块 | 建议占比 | 验收产物 |
|---|---:|---|
| 三个项目与个人叙事 | 25%–35% | 30 秒/2 分钟/10 分钟讲法、指标卡、STAR、追问 |
| Agent / Context / Harness | 20% | 能从状态、工具、循环、安全、观测设计完整系统 |
| RAG / Eval | 15% | 能分阶段评测检索、生成、工具和最终任务 |
| 后端与生产工程 | 15% | 数据库、缓存、MQ、并发、幂等、熔断和排障 |
| Python/算法题/AI Coding | 10%–15% | 限时编码、测试、口述复杂度和使用 AI 的工作流 |
| ML / LLM 基础 | 10% | 能解释 Transformer、训练目标、指标和泛化 |
| 后训练概念 | 5% | 能比较 SFT/LoRA/DPO/PPO/GRPO，不虚构实践 |

临近具体面试时，以 JD 为准重新分配。Applied ML 岗提高 ML 和项目比例；平台岗提高系统设计和后端比例。

## 2. 掌握层级

每个主题用四级标记，不再用“看过/没看过”：

- L1 定义：能用自己的话解释是什么；
- L2 比较：能说明与相邻方案的边界和取舍；
- L3 设计：给定业务场景能画架构、定指标、处理失败；
- L4 证据：能用自己的项目、代码或实验说明真正做过。

面试主线主题至少到 L3，项目核心主题必须到 L4。后训练等非主线主题到 L2 即可。

## 3. 每日闭环

```text
输入：目标 JD / 一个薄弱主题 / 一段项目材料
  ↓
学习：只补回答问题所需的原理
  ↓
输出：口述、架构图、代码或评测表
  ↓
检验：无笔记复述 + 递进追问 + 限时实现
  ↓
复盘：记录不会的点和下一次复习日期
```

每天至少产出一件可复用资产，不能只看文章或视频。

## 5. 时间不足时的最小版本

每天只有 3 小时：

- 45 分钟：Python/算法题；
- 75 分钟：当天主题；
- 45 分钟：一个项目口述或追问；
- 15 分钟：无笔记复盘与记录。

每天有 5–6 小时：在上面基础上增加一个系统设计/AI Coding 练习，以及 30–45 分钟的基础补课。

## 6. 怎样算真的会了

- 不能看笔记，90 秒讲清一个项目；
- 能解释指标口径和一个反例；
- 能画出正常路径、失败路径和人工边界；
- 面试官改变一个约束后，能调整设计而不是背答案；
- 编码完成后主动给测试、复杂度和失败边界；
- 明确区分真正做过、离线验证过和只设计过。
