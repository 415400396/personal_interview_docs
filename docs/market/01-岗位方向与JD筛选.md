# 岗位方向与 JD 筛选

更新日期：2026-09-04

这份文档保存长期有效的筛选方法。具体在招岗位会变化，当前岗位放在同目录的日期快照中。

## 1. 主结论

推荐职业定位：

> 有传统 AI/ML 和研究背景，能够把 Agent、RAG 与业务数据接入生产系统，并对效果、工程稳定性和高风险执行边界共同负责的 AI Application / Agent Engineer。

建议投递结构：

| 方向 | 建议占比 | 定位 |
|---|---:|---|
| AI 应用研发 / Agent 开发 | 65%–70% | 主投 |
| 应用型 Agent Infra / AI 平台 | 15%–20% | 定向投 |
| 业务机器学习 / Applied ML | 10%–15% | 第二优势 |
| Agent/LLM 算法 | 少于 10% | 仅 JD 高度匹配时冲刺 |
| 基座模型训练 / 底层训练 Infra | 第一阶段接近 0 | 不作为当前主线 |

比例不是硬性 KPI。它的作用是避免被“大模型算法工程师”这个模糊标题带偏。

## 2. 不看岗位名，先看职责正文

### 2.1 优先关键词

正文出现越多，越接近当前优势：

- Agent 应用、任务规划、工具调用、Workflow、Router；
- Context Engineering、Memory、Harness、Skills；
- RAG、混合召回、Rerank、知识更新和检索评测；
- MCP、Function Calling、结构化输出和工具 Schema；
- Agent Eval、Golden Set、轨迹回放、Badcase 归因；
- 延迟、成本、稳定性、熔断、降级、权限、安全和可观测性；
- Python/Java/Go、API、数据库、缓存、消息队列和微服务；
- 从业务问题抽象到上线闭环、真实用户或生产环境。

### 2.2 谨慎关键词

可以投，但要看它们是“主体”还是“加分项”：

- SFT、LoRA/QLoRA、DPO；
- 多模态/VLM；
- 分布式推理、Kubernetes、容器；
- 多 Agent 和强化学习；
- LangGraph、Spring AI 等具体框架。

如果职位允许用 Prompt/RAG/Workflow/Eval 解决大多数任务，只把轻量微调作为可选手段，仍然匹配。若日常主体是训练数据、Reward、RL 和大规模训练，则要降级。

### 2.3 暂不主投关键词

正文以这些内容为核心时，当前投入产出比低：

- 预训练、持续预训练、大规模后训练；
- RLHF、PPO/GRPO、Reward Model、RL 算法创新；
- Megatron、DeepSpeed、VeRL、万卡训练；
- CUDA Kernel、通信算子、训练框架性能；
- 虚拟机、容器控制面、块存储、虚拟网络和跨地域一致性；
- 强具身控制、真机强化学习和机器人数据闭环。

注意：“Agent Infra”可能是 Agent 运行平台，也可能是虚拟化基础设施，必须逐条读职责。

## 3. 100 分 JD 评分卡

| 维度 | 权重 | 怎样评分 |
|---|---:|---|
| 项目直接匹配 | 25 | 阈值系统、时效模型或研究经历能否成为直接证据 |
| Agent 应用主线 | 20 | Agent/Tool/RAG/Context/Eval 是否为主要职责 |
| 生产工程匹配 | 15 | Java/Python、服务、数据、审批、审计和排障是否有价值 |
| 结果与评测匹配 | 15 | 是否重视 Golden Set、Badcase、观测、延迟和成本 |
| 基础要求可达 | 10 | 年限、学历、地点、语言和行业门槛 |
| 补课成本 | 10 | 面试前能否用 1–3 周补到可讨论程度；分越高成本越低 |
| 兴趣与长期性 | 5 | 是否愿意连续做两年以上 |

负向扣分：

- 核心职责要求本人没有的预训练/RL ownership：-20；
- 核心职责是底层虚拟化/CUDA：-20；
- 简历必须依赖当前无法证明的城市诊断上线结果才能匹配：-15；
- 工作内容与标题明显不一致：-10；
- 地点、年限或学历为硬门槛且不满足：直接停止。

建议动作：

| 得分 | 动作 |
|---:|---|
| 80–100 | A 档，定制简历并优先联系 |
| 65–79 | B 档，补 1–2 个明显缺口后投递 |
| 50–64 | C 档，只在公司/方向特别想去时冲刺 |
| <50 | 暂不投，避免消耗准备时间 |

## 4. 针对不同岗位怎样选项目

### AI 应用 / Agent 开发

主项目：车辆阈值智能调整系统。

重点：受控领域命令、知识范围、程序校验、人审、审计、42 条金标和真实日志回放。城市诊断只作为“如何从执行工具演进为诊断 Agent”的系统设计题。

### Applied ML

主项目：全国换电工单时效预测。

重点：Label、日期 OOT、同工单、公平分桶、特征价值、长尾取舍、旧运行环境交付和线上评估。不回避只改善 2.30% 和短时桶退化。

### 应用型 Agent 平台

主项目：阈值系统；辅助项目：城市诊断设计。

重点：状态机、工具契约、Context、重试、幂等、异步回调、权限、可观测性和 Eval。要补一个个人可公开运行的小型 Agent Runtime/Harness 作品。

### 多模态 / 生成模型

主经历：USC ICT 论文与南湖相关研究；滴滴项目证明生产能力。

重点：把离散生成、动作/视频研究与现代 VLM/Multimodal Agent 串起来。当前证据较旧，需针对具体 JD 补新模型和可演示作品。

## 5. Java 与 Python 的定位

- Java/Spring：证明能处理领域模型、审批、数据库、异步链路和生产排障；
- Python：作为 AI 应用、数据实验、评测和面试编码的主语言恢复；
- SQL/Spark/Hive：证明能定义样本、审计数据和处理时序口径；
- C++/CUDA/Triton：只在对应研究经历中准确说明，不作为当前主线承诺。

不要把自己投成纯 Java 后端，也不要因为不会大规模 RL 就放弃所有“大模型”岗位。真正的分界是工作主体。

## 6. 投递前五分钟检查

1. 这个岗位一周里最可能花时间做什么？
2. JD 的前三项职责能否分别找到自己的证据？
3. SFT/RL 是手段、加分项，还是岗位主体？
4. “Infra”是在做 Agent Runtime，还是 VM/存储/网络？
5. 需要真实上线 Agent 时，我能否用阈值系统而不是未上线设计回答？
6. 哪三条简历 Bullet 要为这个岗位替换？
7. 最容易把我问住的两个缺口是什么，是否值得为它补课？

## 7. 推荐自我定位用语

推荐：

> 我有算法研究和业务机器学习背景，最近的核心工作是把 LLM/Agent 接入高风险业务流程。我既能做数据、模型和离线评测，也能用 Java/Python 把结构化输出、工具、规则、审批和审计做成生产闭环。

避免：

- “我是大模型全栈，预训练、Agent、后端什么都能做”；
- “我是纯大模型算法工程师”；
- “我只是 Java 后端转 AI”；
- “城市诊断 Agent 已经全自动上线”。
