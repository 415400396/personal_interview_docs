# 历史 GPT 建议摘要

来源：截至 2026-09-04 的一份 2,576 行历史对话粘贴记录。

原记录包含多轮相互修正的建议。本文件只保留最后形成的稳定判断，避免未来把早期、已被推翻的方案重新采用。

## 1. 最终采用的职业判断

- 主线是 AI 应用研发 / Agent 开发，不是基础模型训练；
- Agent Infra 只投应用平台/Runtime/Context/Memory/Eval 类型，不投虚拟化和底层训练 Infra；
- Applied ML 是重要第二优势，时效项目负责证明；
- Java/Spring 是工程落地证据，主语言定位仍应回到 Python AI 应用；
- Transformer、SFT、LoRA、DPO、PPO、GRPO 学到能理解和讨论，第一阶段不以能训练大模型为目标；
- 最大 ROI 是把真实项目、指标和决策重新掌握，再补 Context/Harness/RAG/Eval 和编码。

## 2. 最终采用的投递比例

- 65%–70%：AI 应用研发 / Agent 开发；
- 15%–20%：应用型 Agent Infra / AI 平台；
- 10%–15%：业务 ML / Applied ML；
- 少于 10%：特别匹配的 Agent/LLM 算法；
- 第一阶段基本不投基础模型预训练和底层训练 Infra。

具体比例会随真实面试反馈调整，不能机械执行。

## 3. 最终采用的复习框架

- 项目与个人叙事；
- Agent / Context / Harness；
- RAG / Eval；
- 数据库、缓存、MQ、并发与可靠性；
- Python 算法题、PyTorch 手写和 AI Coding；
- Transformer 与基本后训练概念。

历史建议中曾把 LLM 算法和后训练放得更重，后来基于岗位正文重新判断，已不采用早期配比。

## 4. 对 AI Coding 的最终判断

日常使用 Codex/AI 编程不是能力缺陷，前提是自己能：

- 澄清需求和成功标准；
- 拆分任务并限定权限；
- 审查假设、数据泄漏和指标；
- 看懂 diff，设计测试并验证；
- 发现模型输出错误并独立修正；
- 在没有工具时仍能完成基础编码。

面试训练采用“两遍法”：先独立思考和编码 15–30 分钟，再用 AI 审查，最后关闭 AI 重新解释或重写关键部分。

## 5. 不再采用的内容

- 根据单日职位搜索得出永久职业结论；
- 认为所有“大模型岗位”都必须有 RLHF/GRPO；
- 以职位标题而不是职责正文分类；
- 同时主攻 Agent、基座训练、后端和 Infra；
- 大量堆砌框架名但没有项目输出；
- 把城市诊断方案自动当成上线成果；
- 把版本、配置和普通线上实现细节当作项目卖点。

## 6. 如何使用旧记录

旧记录仍可用来寻找题目和灵感，但涉及岗位有效性、日期、公司流程或技术版本时必须重新查询。涉及个人项目事实时，以 `docs/evidence/` 为准，而不是以聊天中的表述为准。
