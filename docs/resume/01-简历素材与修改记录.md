## 3. 滴滴经历候选结构

简历篇幅有限时，建议只保留两个正式项目：

1. 全国换电工单时效预测；
2. 车辆阈值智能调整与 Agent 接入。

城市诊断 Agent 当前并入第二个项目的一条“演进设计”，不单列为已上线项目。

### 3.1 全国换电工单时效预测

候选 Bullet A：

> 负责既有全国换电工单时效模型的后续演进，从业务 Label、181 日近 783 万行时序数据审计和日期 OOT，到 87 维 XGBoost 训练、Java 运行环境交付与线上评估；建立同工单和分层评测，主动识别标签语义迁移造成的伪提升。

候选 Bullet B：

> 在 318,499 条、228 城公平同工单上，将 MAE 从 126.84 降至 123.91（-2.30%），Spearman 从 0.4965 提升至 0.5280，196 城改善；通过分桶揭示收益主要来自 2 小时以上样本，并明确披露 30–60 分钟桶退化 6.03 分钟。

候选 Bullet C：

> 通过宽幅消融和 permutation 验证特征价值，将旧 115 维链路收敛为 87 维输入；在旧版 XGBoost Java 运行约束下交付 536 树 CPU 模型，99/99 验证通过，同一特征向量线上/本地预测差异约 0.399 分钟。

候选 Bullet D：

> 建设 217 城、62 天、34.73 万行的小时级评估体系，联合城市中位数、分时段、异常日和天气背景分析上线前后变化，避免将城市背景或异常日造成的描述性差异误报为模型因果收益。

最终建议从 A+B+C 或 A+B+D 中选 2–3 条，不必把所有指标都塞进简历。

### 3.2 车辆阈值智能调整与 Agent 接入

候选 Bullet A：

> 负责车辆阈值智能调整核心链路，将运营自然语言转换为受控领域命令：用权威实体知识限定城市/运营区范围，以 Java 完成字段、取值、动作互斥和批量完整性校验，再经配置预览、人工确认、BPM、确定性执行和审计完成高风险修改。

候选 Bullet B：

> 建设基础、批次和日期特例的分层配置语义，支持相对/绝对调整、复制、固定阈值等复杂操作；将人工入口与外部 Agent 结构化入口隔离，上游已有固定 payload 时直接校验和转换，避免二次 LLM 引入漂移。

候选 Bullet C：

> 基于 42 条领域金标、239 次模型调用完成模型与参数评测；最终离线候选裸通过 40/42，经 Java 后置校验为 41/42、0 截断。43 条真实请求回放中平均延迟由 34.43 秒降至 7.17 秒，但一次业务可接受为 40/43、低于原链路 41/43，因此进一步设置批量完整性校验而非只按速度替换。

候选 Bullet D：

> 在现有安全执行底座上设计城市异动诊断 Agent 演进方案，用只读数据工具、状态化 Workflow 和证据评分编排异常识别、假设下钻、建议生成、Dry Run、人工审批和效果回看，并设置 ABSTAIN、幂等和回滚边界。

D 只能写“设计”，不能写“已正式上线”。如果简历篇幅紧，D 可以删除而不是硬凑第三个项目。
